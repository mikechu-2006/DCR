# (玩家, 曲目) cell 内的游玩顺序规律

**问题**：对同一个 (玩家, 曲目) 对，历次游玩的成绩随「累计游玩次数」怎么变？
**数据**：`charts_v2_{1k,10k}_v3.parquet` 的 **primary** cell + 对应的 `plays_v2_{tag}_v3.parquet`。
**脚本**：`scripts/play_order_curve.py`（产物在 `data/processed/order_curve_*`，图在 `docs/figs/order_*`）。

| | 1k | 10k |
|---|---|---|
| primary cells | 141,477 | 1,237,444 |
| 落在 primary cell 内的成绩 | 698,173 | 6,455,660 |
| cell 大小中位 / 均值 | 4 / 4.9 | 4 / 5.2 |
| 时间跨度中位 | 0.92 年 | 0.72 年 |

## 0. 定义

```
pos  = 该成绩在 cell 内按 (year, doy) 排序后的序号 (0-based)
n    = cell 内被记录的成绩条数
p    = (pos + 0.5) / n         ∈ (0,1)     -- 百分位（浮点）
cum  = p * attempts                        -- 估计「到这把为止一共玩了几次」（含失败/重开）
loss = log(1-ACC)  ≤ 0
```

> **符号约定（必须先看）**：`loss = log(1−ACC)`，**ACC 越高 → loss 越小（越负）**。
> 所以「成绩变好」= loss 下降 = 曲线向下。本文所有 loss 曲线都按这个方向读。

所有曲线给两个口径：**per-play**（每条成绩等权，大 cell 权重高）与 **per-cell**（先算 cell 内均值再对 cell 平均）。两者几乎完全重合（见 `order_curve_*_curves.csv` 的 `loss_centered` / `loss_centered_cellmean` 两列），说明结论不是被少数大 cell 带出来的。

## 1. 主结论：**越打越好，单调、有饱和**

### 1.1 百分位曲线

| 百分位 | mean ACC (1k) | mean ACC (10k) | loss−cellmean (10k) |
|---|---|---|---|
| 0.00–0.05 | 0.9523 | 0.9450 | +0.66 |
| 0.10–0.15 | 0.9709 | 0.9613 | +0.44 |
| 0.25–0.30 | 0.9754 | 0.9664 | +0.23 |
| 0.45–0.50 | 0.9746 | 0.9687 | +0.06 |
| 0.50–0.55 | 0.9816 | 0.9746 | −0.01 |
| 0.70–0.75 | 0.9805 | 0.9759 | −0.25 |
| 0.85–0.90 | 0.9857 | 0.9809 | −0.43 |
| 0.95–1.00 | 0.9854 | 0.9823 | −0.73 |

单调上升，中间没有拐点。**第一把显著差**（head 第 1 把 loss−cellmean = **+0.485**（1k）/ **+0.442**（10k），第 2 把骤降到 +0.106 / +0.13，之后平缓）——第一把是「生手读谱」，后面才是稳定水平。

### 1.2 cell 级统计

| 量 | 1k | 10k |
|---|---|---|
| 第一把 mean ACC | 0.97126 | 0.96190 |
| 最后一把 mean ACC | 0.98620 | 0.98139 |
| **ΔACC（最后−第一）** | **+1.49 pp** | **+1.95 pp** |
| ΔACC 中位数 | +0.68 pp | +1.19 pp |
| **ΔACC > 0 的 cell 占比** | **77.9%** | **83.0%** |
| 斜率 d(loss)/d(percentile) 中位 | −0.910 | −0.905 |
| 斜率 < 0（在进步）占比 | 79.6% | 84.1% |
| 斜率 > 0（在退步）占比 | 13.1% | 12.5% |

**个人最好成绩在哪**：`p_best` 中位 = **0.833**；61.0% 的 cell 最好成绩落在最后 25% 的历史里，只有 11.2% 落在最前 25%。个人最差成绩 `p_worst` 中位 = 0.167（即最前面）。

不过「最后一把 = 个人最好」只有 **0.28%** 的 cell——最好成绩平均还比最后一把高 **0.28 pp**，说明末把仍然不是峰值，标签取「全 cell 中位」而不是「末把」是有道理的。

### 1.3 学习曲线的形状（固定 cell 集合）

把 cell 集合固定住（只取 n ≥ K），再看第 k 把的平均 ACC，排除「不同 n 的 cell 组成不同」的干扰：

| 第 k 把 | K=5 | K=10 | K=20 | K=50 |
|---|---|---|---|---|
| 1 | 0.9559 | 0.9466 | 0.9368 | 0.9325 |
| 2 | 0.9638 | 0.9543 | 0.9449 | 0.9390 |
| 5 | 0.9749 | 0.9645 | 0.9543 | 0.9466 |
| 10 | — | 0.9753 | 0.9634 | 0.9535 |
| 20 | — | — | 0.9762 | 0.9623 |
| 30 | — | — | — | 0.9678 |
| 50 | — | — | — | 0.9784 |

（10k 数据）**前半段陡、后半段平**：n≥50 的 cell 里，前 10 把涨 +2.7 pp，第 10→50 把只再涨 +3.1 pp。从末端往回看（`tail_acc`）几乎是一条平线（0.9759…0.9770），即**打到几十把之后基本进入平台**。

### 1.4 用「累计游玩次数」当横轴

`cum = percentile × attempts`（attempts 是含失败/重开的真实 playcount）：

| 累计次数 | mean ACC (10k) | loss−cellmean |
|---|---|---|
| <1.5 | 0.9616 | +0.43 |
| 1.5–2.5 | 0.9654 | +0.31 |
| 2.5–3.5 | 0.9698 | +0.13 |
| 4.5–6 | 0.9710 | +0.05 |
| 8–11 | 0.9730 | −0.05 |
| 15–21 | 0.9748 | −0.15 |
| 29–40 | 0.9764 | −0.23 |
| 55–76 | 0.9772 | −0.29 |
| 105–145 | 0.9771 | −0.33 |
| 200–275 | 0.9776 | −0.39 |
| 380+ | 0.9723 | −0.35 |

**近似 log-linear 后饱和**：ΔACC ≈ **0.0134 × ln(n)**（10k 回归，截距 −0.0007）；等价地 `slope_logcum` 中位 −0.323 loss / 每 e 倍次数。ACC 在累计 **≈60–100 次**之后进入平台（0.9775 左右），超过 ~300 次反而略降（这多半是 composition：能把一张图打 300 次的玩家玩的图偏难）。

## 2. 稳健性：这个规律不是抽样/记录偏差造成的

### 2.1 按「记录完整度」 n/attempts 分层（关键检验）

`osu_scores_mania_high` 只记录了真实游玩的一部分，所以「cell 内顺序」天然和「哪些成绩被记下来」纠缠。如果规律来自「只记好成绩」这种选择偏差，那么记录越不完整的 cell 应该越陡。**实测不是**：

| n/attempts | cells (10k) | ΔACC 均值 | 在进步的 cell 占比 | 斜率中位 |
|---|---|---|---|---|
| 0.0–0.2 | 362,088 | +1.93 pp | 81.4% | −0.897 |
| 0.2–0.4 | 366,150 | +1.97 pp | 84.1% | −0.926 |
| 0.4–0.6 | 230,788 | +2.07 pp | 84.7% | −0.920 |
| 0.6–0.8 | 167,364 | +1.90 pp | 82.8% | −0.889 |
| 0.8–1.0 | 111,053 | +1.77 pp | 81.4% | −0.853 |

**几乎完全平坦**。记录最完整的 cell（≥80% 的尝试都留下了成绩）和最稀疏的 cell 曲线一样。→ 规律来自玩家行为，不是记录筛选。

### 2.2 其余分层（10k）

| 维度 | ΔACC 均值 | 在进步占比 |
|---|---|---|
| rate NM / DT / HT | +1.89 / +2.19 / +2.47 pp | 81.9% / 87.5% / 93.5% |
| star <3 / 3-4 / 4-5 / 5-6 / 6-7 / 7+ | +1.24 / +1.59 / +1.79 / +1.96 / +2.21 / **+2.37** pp | 49% / 72% / 81% / 85% / 88% / **91%** |
| cell 大小 n=3 / 4-5 / 6-10 / 11-20 / 21-50 | +1.45 / +1.84 / +2.51 / +3.53 / **+4.67** pp | 79% / 83% / 87% / 90% / **91%** |

* **越难的图学习曲线越强**（7★ 以上 ΔACC +2.37 pp、91% 的 cell 在进步；3★ 以下只有 +1.24 pp、49%）。这与「难图才有可学的空间」一致。
* **打得越多的 cell 提升越大**，与 log-linear 学习曲线一致。
* DT/HT 比 NM 更陡：变速档位的适应成本更高。

### 2.3 「反复打」和「时间流逝」的分解

按 cell 首末成绩的时间跨度分层（10k）：

| 跨度 | cells | 第一把 ACC | 最后一把 ACC | ΔACC |
|---|---|---|---|---|
| 同一天 | 18,998 | 0.9811 | 0.9881 | **+0.70 pp** |
| <7 天 | 30,758 | 0.9672 | 0.9779 | +1.07 pp |
| >1 年 | 470,008 | 0.9639 | 0.9844 | **+2.05 pp** |

同一天内的重复（纯「打几把就熟」）已经能带来 +0.70 pp；跨年的 cell 再多 +1.35 pp（长期水平增长 + 反复练习的叠加）。两者同向，说明「次数」本身就有因果作用，不只是时间代理。

## 3. ⚠️ 顺带发现：项目文档里的 loss 符号写反了

`build_v2.py` 定义 `loss = log1p(-acc)`，即 `loss = log(1−ACC)`。这是 **ACC 的单调递减函数**：

| ACC | 0.90 | 0.95 | 0.98 | 0.99 | 0.995 |
|---|---|---|---|---|---|
| loss | −2.303 | −2.996 | −3.912 | −4.605 | −5.298 |

但下列文档/注释写成了「loss 越大 = ACC 越高」（即方向相反）：

* `README.md` §4.2：「**判据**（…，loss = log(1−ACC)，**越大 = ACC 越高**）」
* `scripts/legacy/convergence_filter.py` 模块 docstring：「注意 loss = log(1-ACC)，**越大 = ACC 越高**。实测后窗普遍比前窗低（认真推分 -> 之后随手打）」
* `docs/cleaning_plan.md` §2.3 判据表：`delta / adelta | mean(末窗) − mean(前窗) / 其绝对值（**loss 越大 = ACC 越高**）`

**后果（两处结论被反向）**：

1. README §4.2 的「反直觉的事实」——「n≥6 的 cell 里 85% 的 `delta < −0.05`（后窗比前窗低）…也就是说排到最后的那些成绩往往是『认真推过分之后随手打』的，**不是学习曲线**」。
   按正确符号，`delta < 0` 意味着**后窗 loss 更低 = ACC 更高 = 打得更好了**。**这恰恰就是学习曲线**，而且是本节第 1 部分独立复现的结论（10k 里 84.1% 的 cell 在进步）。项目自己的数字（85%）完全支持学习曲线，只是结论句写反了。
2. 同段的「末窗通常不是个人最好水平（`l_max − mean(末窗)` 中位 0.73）」：`l_max` 是**最大** loss = **个人最差**成绩，这个统计量不支持那句话。正确的检验应该用 `l_min − mean(末窗)`。实测：最好成绩平均只比最后一把高 **0.28 pp**，`p_best` 中位 0.833——**末窗其实相当接近个人最好水平**。

`convergence_filter.py` 的 docstring 里「正 = 后来越打越好」同样应改成「正 = 后来越打越差」。

**影响范围**：判据本身（`|delta| ≤ δ`、`sd_tail`、`se_tail`）不受符号影响，因为都取了绝对值；受影响的只是**文字结论**，以及「为什么要取绝对值」的论证（原论证是「85% 在退步，所以不要求越打越好」；正确的事实是「85% 在进步，所以不要求『末窗≈个人最好』」——结论仍是取绝对值，但理由不同）。

## 4. 对建模的直接含义

1. **cell 标签用「全 cell 中位」是对的**，不要换成末把或末窗：最好成绩平均比最后一把还高 0.28 pp，末窗有系统性乐观/悲观偏移；而全 cell 中位把「早期生手」和「后期平台」都平均进去了。
2. **收敛判据的 `trend`（长期斜率）现在可以直接量化**：`slope_p` 中位 −0.905（loss/百分位），10k 里 84% 的 cell 显著为负。它是 `docs/cleaning_plan.md` §2.3 表里那个「趋势」量的现成实现，`data/processed/order_curve_{tag}_cells.parquet` 已经按 cell 存好。
3. **cell 大小本身带信息**：n 越大，学习曲线越陡（ΔACC +1.45 pp @n=3 → +4.67 pp @n=21-50）。如果模型不显式建模「cell 内的位置」，那么不同 n 的 cell 标签含义不同（n=3 的 cell 中位更接近「新手水平」，n=30 的更接近「平台水平」）。这正是 `convergence_filter` 想解决的问题，方向是对的。
4. **`n_scores ≤ 2` 的剔除是合理的**：n=3 的 cell 里 21% 是在退步的（且第一把占的权重大），噪声最大。
5. 如果以后要做「同一玩家同一图跨时间」的预测，可以直接用「累计游玩次数」当特征，形式取 `ln(cum)`（ΔACC ≈ 0.0134·ln(n)）。
6. **学习率的异质性**（它在不同谱面/玩家之间差多少、loss 单位下是什么样）见
   **[learning_rate_heterogeneity.md](learning_rate_heterogeneity.md)**：per-cell `beta_loss` 均值 −0.377（10k），
   方差分解为 玩家 35% / 谱面 10% / 交互 31% / 噪声 24%（n≥12）。

## 6. 已知局限

* **观察到的成绩不是全部游玩**：`osu_scores_mania_high` 只含约 1/3 的尝试（≈ 通过的那些）。§2.1 已证明这**没有**造成顺序偏差，但「累计次数」是用 `percentile × attempts` 估的，`attempts` 是 (玩家, **谱面**) 级、跨速率共享，所以 DT/HT cell 的 `cum` 偏大。
* **同一 (year, doy) 内没有更细的时间戳**，同日多把的顺序用 score_id（提交顺序）稳定排序，等价于真实顺序。
* **百分位分箱在小 n 下是离散的**（n=3 → p ∈ {1/6, 1/2, 5/6}），所以 §1.1 的百分位曲线有轻微锯齿
  （±0.002 ACC），位置曲线（§1.3）也有约 ±0.001 ACC 的偶奇波动。以 **§1.3 的固定 cell 集合曲线**为准。
* 只统计 **primary** cell（剔除了乱打、playcount≤2、n_scores≤2）。未过滤池里规律更弱（第一把的「生手效应」被乱打稀释）。
