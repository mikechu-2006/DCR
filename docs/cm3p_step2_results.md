# CM3P × step2 接入：实现与实测（v2：冻结内容向量 + 纯点积）

> 对应方案：[docs/cm3p_step2_integration_plan.md](cm3p_step2_integration_plan.md)。
> 本文记录 **2026-10-09 的实际实现与全部实跑数字**；方案文档只描述设计。
> 所有 RMSE 都是 **step0 测试口径**（train 读 step1、test 读 step0，30% 有序对，seed `20260928`），
> 引擎 torch 2.13.0+cpu、`deterministic_algorithms=True`、60 epoch。

---

## 0. 一句话结论

1. **管线通了**：`L_hat = b0 + bu[u] + bm[m] + <P_u, C_m>`，`C_m` 是冻结的 CM3P 向量（512 维 → PCA `d`），
   `P` 与 `C` 同维；`mirt`/`D` 完全没用上。
2. **内容向量替换 1-hot：同口径下不劣、略优**。覆盖子集上 `d=32` 拿到 **1.57595**，
   1-hot baseline 是 **1.58147（d8）/ 1.58314（d16）**；同时**删掉了 11,214×16 ≈ 17.9 万个 per-chart 自由参数**。
3. **真实时间戳漂移是本次最大的发现**：全表 `mf_dot` dim16 从 **1.45484 → 1.37173（−5.7%）**。
   这比本地 dim 扫描的最优值 **1.454837** 好，也比此前 1k 全表的最好成绩
   **1.421598**（`mirt` F1+pd dim8）好。
4. **漂移的"轴"比"有没有漂移项"更重要**：同为 `mf_dot` dim16、同一子集，
   `--p-drift time` 提升 **6.1%**，`--p-drift logpc`（练习次数轴）只提升 **1.5%**。
5. **512 维原样使用是最差的一档**（覆盖子集 1.59759，比 baseline 还差）——与方案 §4.3 的预判一致。

## 2. 两条管线的契约（已落地）

    .osu / HF 244K ──► step0c_chart_content.py ──► chart_content_cm3p.parquet
                                                          │  只读
    step0/step1 play 表 ──► 过滤到有向量的谱面 ──► 30% 有序对划分 ──► step2_predict.py

* **管线解耦已验证**：`step2_predict.py` 不 import `transformers`、不依赖 `external/cm3p`，
  只读一张 parquet。
* **先过滤后划分**：过滤发生在 split 之前。覆盖子集的 pair 池 = **612,997**（不是 866,616），
  训练 play **378,750**、测试 play **267,368**。
* **新增第 10 条 checklist**：`content_aligned_with_item_ids`
  （C[i] 必须属于 item_ids[i]；行范数 = 1）。每次运行都跑，失败则不写产物。
* **幂等**：`step0c` 重跑第二次时输出 `to fetch: 10,072 (already present: 11,877)`，
  扫描后 0 新增，表保持 11,877 行。

## 3. 两个口径，先说清楚

### 3.1 对照目标：本地 dim 扫描的最优值

从 `data/processed/step2_1k_summary_loss.json` 读出的既有扫描（全表、60 epoch、step0 RMSE）：

| 模型 | dim2 | dim3 | dim4 | dim8 | dim16 |
|---|---|---|---|---|---|
| `mf_dot` | 1.477674 | 1.467428 | 1.462825 | 1.455562 | **1.454837** ← 扫描最优 |
| `mirt` | 1.478150 | 1.468849 | 1.465215 | 1.458237 | 1.458235 |

此前 1k 全表的**总最好**成绩是 `mirt` + F1 + `--p-drift logpc`：dim8 **1.421598**、dim16 1.422548。
⇒ 本文的对照线：**1.454837（同族 dim 扫描最优）** 与 **1.421598（历史总最好）**。

⚠️ **不要拿 [docs/step2_capacity_dim_sweep.md](step2_capacity_dim_sweep.md) 里的数字当对照线。**
那是**另一套诊断实现**（per-group lr + ALS 热启动 + 早停，标签标准化），它自己的口径警告写明
"绝对值不可跨文档比较"：它的 K=0 基线是 **1.5708**，而 `step2_predict.py` 的 `bias` 是 **1.5236**。
本文所有数字都出自 `step2_predict.py`，所以对照线只能是同一脚本的乘积。

### 3.2 覆盖子集不等于全表 —— 所以 baseline 必须重跑

内容表只覆盖 21,949 张白名单里的 **11,877 张（54.11%）**，且被覆盖的几乎全是 `last_update ≤ 2023` 的图。
把 play 表限制到这个子集后，**任何一种"按谱面参数化"的模型都变差**，与内容无关：

| 模型（ALS 闭式解，同一 split） | 全表 | 覆盖子集 | 差 |
|---|---|---|---|
| 常数 `b0` | 2.1699 | 2.1702 | +0.000 |
| `b0 + b_u` | 2.3116 | 2.3098 | −0.002 |
| `b0 + b_m` | 1.8791 | 1.9276 | +0.049 |
| **`b0 + b_u + b_m`** | **1.5177** | **1.6486** | **+0.131** |

标签本身的离散度**完全一样**（覆盖子集损失 sd 2.1272 vs 全表 2.1437），所以这不是"子集更难预测"，而是子集内部
**train(step1) / test(step0) 的分布位移更大**。机制可以直接量出来 —— step1 清洗规则二是"删每玩家最早的 30%"，
而被删掉的那些早期游玩**高度集中在老图上**：

| 谱面分组 | step0 行数 | 进入 step1 的比例 |
|---|---|---|
| 覆盖子集（≤2023） | 892,156 | **60.67%** |
| 全表 | 1,399,615 | 68.90% |
| 被排除的 2024+ | 507,459 | **83.39%** |

⇒ 覆盖子集里，训练看到的 60.7% 与测试看到的 100% 之间隔得最远。
**结论：跨口径比数字没有意义；A/B 必须落在同一子集上。** 本文所有内容 vs 1-hot 的比较都在覆盖子集内完成。

## 4. 结果

### 4.1 全表：直接对照 dim 扫描（用户要求的比较口径）

| 变体 | dim | 漂移 | step0 RMSE | Spearman | epoch 20 |
|---|---|---|---|---|---|
| `bias` | — | none | 1.52356 | 0.7330 | 1.52078 |
| `mf_dot`（= 扫描最优，复现） | 16 | none | 1.45484 | 0.7632 | 1.44265 |
| **`mf_dot` + 时间漂移** | **16** | **time** | **1.37173** | **0.7919** | **1.35810** |
| `mf_dot` + 时间漂移 | 8 | time | 1.37368 | 0.7912 | **1.34649** |

**读法**：

* 相对同族 dim 扫描最优 **1.454837 → 1.37173 = −0.0831（−5.71%）**；
* 相对历史总最好 **1.421598 → 1.37173 = −0.0499（−3.51%）**；
* Spearman 同时从 0.7632 升到 **0.7919**（+0.029），说明不是靠压缩方差换来的；
* dim8 与 dim16 基本打平（1.37368 / 1.37173）——**加时间漂移之后，低秩的 `d` 不再是瓶颈**。

### 4.2 覆盖子集：1-hot baseline vs CM3P 冻结内容向量

同一子集、同一 split、同一 epoch 数（60），`--models mf_dot`：

| 模型 | dim | step0 RMSE | epoch 20 | 每谱面自由参数 |
|---|---|---|---|---|
| `bias` | — | 1.63750 | 1.61444 | 1（`bm`） |
| 1-hot | 8 | 1.58147 | 1.55197 | 8（`C`）+ 1 |
| 1-hot | 16 | 1.58314 | 1.54577 | 16 + 1 |
| **CM3P** | **8** | 1.58514 | 1.54534 | 1 |
| **CM3P** | **16** | 1.57956 | 1.53945 | 1 |
| **CM3P** | **32** | **1.57595** | **1.53655** | 1 |
| **CM3P** | 64 | 1.57984 | 1.54334 | 1 |
| **CM3P** | 128 | 1.58787 | 1.55464 | 1 |
| **CM3P** | 512（raw） | 1.59759 | 1.56949 | 1 |

**读法**：

* 内容是**有效的**：`d ∈ {16, 32, 64}` 都优于 1-hot，最好在 **d=32 = 1.57595**
  （比 1-hot d8 好 0.0055 / 0.35%，比 1-hot d16 好 0.0072 / 0.45%；epoch 20 的差距更大：0.0092 / 0.60%）；
* 代价是**零**：per-chart 自由参数从 11,214×16 = 179,424 降到 11,214（只剩 `bm`），
  谱面侧少了 **17.9 万**个参数，测试误差还更低；
* **`d` 有内部最优（32）**，两头都差：`d=8` 容量不足，`d≥128` 开始过拟合，
  **512 维原样使用是全局最差（1.59759，比 baseline 还差 0.9%）**——这正是方案 §4.3 用参数量预判过的结果；
* 曲线在 epoch 20 之后全部回升（子集小、60 epoch 过量），但**两个模型族的回升速度一致**，排序不变。

### 4.3 时间漂移消融（覆盖子集，`mf_dot` dim16/32/64）

| 模型 | 无漂移 | `logpc`（练习次数轴） | **`time`（真实时间戳轴）** | time 相对无漂移 |
|---|---|---|---|---|
| 1-hot d16 | 1.58314 | 1.55912（−1.52%） | **1.48710** | **−6.06%** |
| CM3P d16 | 1.57956 | 1.55718（−1.42%） | 1.51879 | −3.85% |
| CM3P d32 | 1.57595 | — | 1.53122 | −2.84% |
| CM3P d64 | 1.57984 | — | 1.54618 | −2.13% |

**读法**：

* **轴的选择比"加不加漂移项"重要 4 倍**：同样多的参数（983×dim），沿真实时间漂移拿到 −6.1%，
  沿 `ln(playcount_cur)` 漂移只拿到 −1.5%。仓库此前只有后者。
* **内容模型从漂移里获益更少**（−3.9% vs −6.1%）。合理解释：1-hot 的自由 `C` 表能把
  "随时间变化的谱面难度"编码进每个谱面自己的方向，而冻结内容向量的方向是共享的；
  换句话说，**时间漂移与自由谱面因子之间有部分替代关系**。
* 覆盖子集上目前最好的是 **1-hot d16 + time = 1.48710**；内容模型最好的是 **CM3P d16 + time = 1.51879**。
  两者都没有超过全表 + time 的 1.37173 —— 再次说明跨口径不可比（§3.2）。

### 4.4 结论

1. **方案里的三个预判全部被实测确认**：纯点积可行、`d` 必须扫（512 最差）、内容可以硬替换 1-hot。
2. **CM3P 的价值不是"更准"，而是"同样准、少 17.9 万参数、且能外推"**——
   外推能力（冷启动整图留出）本版本还没测，是下一步。
3. **本次最大的收获在方案之外**：玩家向量沿**真实日历时间**线性漂移，比沿练习次数漂移有效得多，
   单这一项就把 1k 全表从 1.4548 推到 1.3717。

## 6. 复现命令

    # 管线 A（一次；重复跑只补缺失的 id）
    python scripts/step0c_chart_content.py --tag 1k

    # 全表：对照 dim 扫描最优值
    python scripts/step2_predict.py --tag 1k --models mf_dot --dim 16 --epochs 60
    python scripts/step2_predict.py --tag 1k --models mf_dot --dim 16 --epochs 60 --p-drift time

    # 同子集 1-hot baseline（先过滤后划分）
    python scripts/step2_predict.py --tag 1k --models mf_dot --dim 16 --epochs 60 \
        --restrict-to-content on

    # CM3P 冻结内容向量：d 扫描
    for d in 8 16 32 64 128; do
      python scripts/step2_predict.py --tag 1k --models mf_dot --epochs 60 \
        --chart-content cm3p --content-dim $d
    done

    # 漂移消融
    for dr in none logpc time; do
      python scripts/step2_predict.py --tag 1k --models mf_dot --dim 16 --epochs 60 \
        --restrict-to-content on --p-drift $dr
    done
