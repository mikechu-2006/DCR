### 0.2 五个判断

1. **评测不确定是真的。** `encode_charts` 只把 encoder 设为 eval，难度头仍在
   train 模式，dropout 继续生效；函数返回时又把 encoder 切回 train。同一权重、
   同一输入连续打分可以得到不同值。见
   [step2_chart_encoder.py:487](../../scripts/step2_chart_encoder.py#L487)。
2. **checkpoint 不能证明是 best。** `best_state` 里的 `state_dict()` 是活引用；
   `save_every` 又用 last 覆盖同名 `checkpoint.pt`。最终恢复的可能是最后权重，
   不是 best。见 [step2_chart_encoder.py:845](../../scripts/step2_chart_encoder.py#L845)
   和 [step2_chart_encoder.py:861](../../scripts/step2_chart_encoder.py#L861)。
3. **BT loss 自己会产生 NaN。** 先 sigmoid 再 clamp 再 log；bf16 下 `d_j-d_i=8`
   时 sigmoid 舍入到 1，`0 * log(0)` 仍是 NaN。已用当前函数复现：
   `bf16: q=1, log1p(-q)=-inf, loss=nan`。见
   [step2_chart_encoder.py:193](../../scripts/step2_chart_encoder.py#L193)。
4. **配对 Δ 和主表不是同一批 pair。** 主表用 ceiling 覆盖的 strict pairs；
   `rank_paired_delta` 枚举所有共同测试图对。player bootstrap 还按
   `player_id` 分段抽样，并用布尔 mask 丢掉重复抽中的次数。见
   [step2_rank_eval.py:309](../../scripts/step2_rank_eval.py#L309) 与
   [rank_paired_delta.py:70](../../scripts/rank_paired_delta.py#L70)。
5. **“评测全部窗口”和“1M 对全量均匀估计”都不准确。** 评测默认只取前
   `max_windows=24` 个窗口；训练是“先均匀抽玩家，再从每人最多抽 6 张图”，
   1M pair views 是该采样策略下的估计，不是从 2.55 亿对里均匀抽。见
   [step2_chart_encoder.py:497](../../scripts/step2_chart_encoder.py#L497) 与
   [step2_chart_encoder.py:262](../../scripts/step2_chart_encoder.py#L262)。

## 2. E1_fix 的口径冻结

### 2.1 数据与划分

* 固定 **H4 seed 1** 做修复；seeds 2–5 只在 M5 通过后跑。
* 这里的“seed”指 **H4 player-split seed**；训练随机种子仍固定 `--seed 0`。
  不要把它和 model seed 混写。
* 主表：`--split test --ceiling-fit all --strict-pairs`。
* 主指标：strict-pair rank-NLL；越小越好。
* 配对：同一玩家段内两张图；ties=0.5；player cluster 用 `player_id_base`，
  chart cluster 用 `beatmap_id`。

### 2.2 主要终点

| 假设 | 对比 | 方向 | 预注册判据 |
|---|---|---|---|
| **H1a** | unfrozen top-4 − frozen same-head | 负 | Δ ≤ −0.003，5/5 split seeds 为负，两个 95% CI 排除 0 |
| **H1b** | unfrozen top-4 − random init | 负 | Δ ≤ −0.005，5/5，两个 95% CI 排除 0 |
| **H1c** | frozen − random | 描述性 | 不单独下结论 |
| **H1-strong-baseline** | unfrozen − 最强冻结读出 | 负 | 只作 secondary；若 CI 含 0，写“打平/未超过” |

“最强冻结读出”至少包括：
1. 同头、K4 的 frozen same-head（原三臂之一）；
2. 同头、全窗口的冻结对照（F4 的 C1）；
3. content-table D2V linear（不同头/聚合，只作外部参照）。

### 2.3 checkpoint 策略（协议修正）

当前报告用 val early-stop 的 best；但三臂实际预算不同（冻结臂 928k，另两臂 1M），
这本身就是混淆。E1_fix 建议：

* **主分析：固定 1,000,000 pair views，不早停，导出 `last.pt`。**
* **secondary：`best.pt`（val 最优）**，只作敏感性分析；若两者结论不同，明确报告。
* 选择规则在看 test 前固定；不允许“哪个 test 好看看哪个”。
* 如果必须保留原预注册的 early-stop，则至少：(a) 主表标注实际 pair views；
  (b) 不写“同预算”；(c) 用 `last` 和 `best` 各报一次。

> 这是 E1_fix 的**测量修正**，不是看到 test 后改终点。建议在跑 clean seed 1 前
> 把这条写进 run config 和报告的方法节。

### 2.4 统计口径

* strict pairs：对每个玩家段，只保留两张图都在该玩家 fold 的
  `seen_folds` 里的 pair。
* player CI：按 `player_id_base` 做 cluster bootstrap；抽中的 base 保留
  multiplicity，不能去重。
* chart CI：按 `beatmap_id` 做 cluster bootstrap；pair 权重为
  `mult[a] * mult[b]`，再乘 strict mask。
* 默认 `B=2000`；最终报告写 `B`、seed、cluster 列。
* 不跨 split seed 合并 NLL；先报每个 seed 的 Δ，再报 5 个 Δ 的均值/符号数。

## 3. F1：确定性评测与 checkpoint

### 3.1 目标

同一 checkpoint、同一 split、同一 `max_windows`、同一 `batch_charts`，
两次独立进程打分得到相同结果；并且能明确知道分数来自 `best.pt` 还是 `last.pt`。

### 3.2 代码改动

#### 3.2.1 eval 模式

在 `scripts/step2_chart_encoder.py` 增加：

~~~python
from contextlib import contextmanager

@contextmanager
def preserve_eval(*modules):
    was = [m.training for m in modules]
    try:
        for m in modules:
            m.eval()
        yield
    finally:
        for m, flag in zip(modules, was):
            m.train(flag)
~~~

`encode_charts` 改为：

~~~python
@torch.inference_mode()
def encode_charts(model, head, cache, chart_ids, args, device, batch_charts=8):
    with preserve_eval(model, head):
        ...
~~~

删除函数末尾的 `model.train()`。这样：

* unfrozen 训练中调用 eval 后，encoder 回到 train；
* frozen 训练中调用 eval 后，encoder 回到 eval；
* head 始终回到调用前的状态；
* 最终导出不再意外把 encoder 留在 train。

同时设置：

~~~python
torch.backends.cudnn.benchmark = False
torch.backends.cudnn.deterministic = True
torch.use_deterministic_algorithms(True, warn_only=True)
~~~

若 GPU 仍不能达到 1e-6，则最终评分允许 `--eval-device cpu` 作为确定性回退；
报告中注明。

#### 3.2.2 checkpoint 分离

新增两个文件：

* `best.pt`：只在 val NLL 改善时写；不参与后续覆盖。
* `last.pt`：每个 `save_every` 和训练退出时写；用于 resume/固定预算分析。

保存前做 CPU clone：

~~~python
def snapshot(module):
    return {k: v.detach().cpu().clone()
            for k, v in module.state_dict().items()}

payload = {
    "format_version": 2,
    "kind": "best" | "last",
    "model": snapshot(model),
    "head": snapshot(head),
    "event_head": snapshot(event_head) if event_head else None,
    "sig_head": snapshot(sig_head) if sig_head else None,
    "opt": opt.state_dict() if kind == "last" else None,
    "step": step,
    "pair_views": pair_views,
    "row_views": row_views,
    "best_val": best_val,
    "best_step": best_step,
    "args": vars(args),
    "git_rev": git_rev(ROOT),
    "config_hash": config_hash,
}
~~~

写文件用临时文件 + `os.replace`，并写 `checkpoint_manifest.json`：

~~~json
{
  "best": {"path": "best.pt", "step": 18000, "pair_views": 928250,
            "val_nll": 0.61812, "sha256": "..."},
  "last": {"path": "last.pt", "step": 19384, "pair_views": 1000013,
            "sha256": "..."}
}
~~~

不要再用 `checkpoint.pt` 这个模糊名字。旧 run 的 `checkpoint.pt` 保持原样，
只在清单里标 `legacy_ambiguous`。

#### 3.2.3 score-only 模式

旧 checkpoint 没有 `args`；score-only 必须允许用 CLI + `--config` 重建架构。
新 checkpoint 有 `args` 时，用其架构参数并校验 CLI 不冲突。

新增 CLI：

~~~text
--score-only
--checkpoint PATH            # 直接给文件（legacy 用这个）
--checkpoint-kind best|last  # 与 --run-dir 搭配
--run-dir PATH               # 新格式 run 目录（含 manifest）
--repeat-eval 2
--eval-batch-charts 8
--max-windows 24|0
--dump-window-coverage
~~~

行为：

1. 只读 checkpoint，不建 optimizer，不训练；
2. 新 checkpoint 从 `args` 读取架构参数（`hid`、`dropout`、`window_sec`、
   `frame_hz`、`sigma_ms` 等）；旧 checkpoint 没有 `args`，用
   `--config` + CLI 重建同样的架构。两种路径都要校验维度；
   CLI 只允许覆盖 eval-only 参数；
3. 对 test/val 各跑 `repeat_eval` 次，比较 `max |d1-d2|` 和 NLL；
4. 写 `d_test.parquet`、`d_val.parquet`、`score_metrics.json`、
   `window_coverage.parquet`；
5. 分数文件用 checkpoint 的 kind/step/哈希命名，例如
   `scores/last_step19384/d_test.parquet`。

### 4.1 代码改动

把 `scripts/step2_chart_encoder.py` 的 `bt_loss` 改成：

~~~python
def bt_loss(d, pi, pj, y):
    if pi.numel() == 0:
        return d.sum() * 0.0
    logits = (d[pj] - d[pi]).float()
    target = y.to(dtype=logits.dtype)
    return F.binary_cross_entropy_with_logits(
        logits, target, reduction="mean")
~~~

要点：

* 在 **FP32 logits** 上算 BCE；不要先 sigmoid 再 log。
* `y` 保留 0/0.5/1；BCEWithLogits 支持软标签。
* 不再需要 `eps` 参数；删除调用处的 `eps`。
* 如果 `d` 是 bf16，`.float()` 只影响 loss，不影响梯度回传的 dtype 路径。

同时把 `dcr/rank_metrics.py` 的 `pairwise_rank_loss` 改为同一实现：

~~~python
logits = beta * (pb - pa).float()
return F.binary_cross_entropy_with_logits(
    logits, y.float(), reduction="mean")
~~~

保留现有 `ties="skip"|"half"` 语义；现有 self-check 应全部继续通过。

### 4.2 测试

在 `scripts/test_rank_metrics.py` 增加：

* bf16 `d=[0,8]`，`y=1`：loss ≈ 3.35e-4，有限；
* bf16 `d=[0,8]`，`y=0`：loss ≈ 8.0003，有限；
* bf16 `d=[0,8]`，`y=0.5`：loss ≈ 4.0002，有限；
* `d=[-1000,1000]`：有限，无 inf/nan；
* 梯度有限：`loss.backward()` 后 `d.grad` 全部 finite；
* 与 float64 参考值误差 <1e-5（非极端区）。

### 4.3 坏 batch 记录

把现在的 `bad_batches` 计数升级为 `bad_batches.jsonl`，每条记录：

## 5. F3：配对 Δ 与 CI 对齐主表

### 5.1 主表的 strict pair 定义

对玩家段 `u`（`player_id`），取其 base cluster `c=player_id_base`，
fold `f = ceiling.fold_of_cluster[c]`，seen mask `S_f`。只保留：

~~~text
i < j
S_f[chart_i] = 1
S_f[chart_j] = 1
~~~

其中 `i,j` 是该玩家段内的两张图；`y=1[loss_i<loss_j]`，ties 0.5。

这正好是 `nll_on_ceiling_pairs` 的 pair 集；主表的 `n_strict` 应等于
`ceiling.n`。

### 5.2 需要补的 ceiling 元数据

当前 ceiling cache 只存 `fold_of_cluster`、`seen_folds`，没有存
`cluster_ids` 和 `map_ids`；配对脚本无法可靠地把 base/chart 映射回去。
修改：

* `dcr/rank_metrics.py` 的 `Ceiling` 增加：
  `cluster_ids`（eval cluster 的排序后 ID）、`map_ids`（eval chart 词汇表，默认 None）；
* `cross_fit_bt` 返回 `cluster_ids`；`map_ids` 由 runner 在保存 cache 时写入
  （`cross_fit_bt` 只认识 `n_items`，不认识原始 beatmap_id）；
* `step2_rank_eval.py` 的 `_save_ceiling` / `_load_ceiling` 保存/读取两者；
* cache key 加 `CACHE_VERSION=2`，旧 cache 不再复用；
* `eval.json` 的 `meta` 写 `ceiling_cache`、`cluster_ids`、`map_ids` 的哈希。

### 5.3 `rank_paired_delta.py` 改造

新增参数：

~~~text
--strict-pairs
--ceiling-cache PATH
--cluster-col player_id_base
--bootstrap 2000
--fit-on all|strict        # 默认 all，和主表一致
--require-full-coverage    # 默认 true
--expected-n-strict N      # 可选，来自主表 eval.json
~~~

流程：

1. 读输入表，过滤 `split == "test"`；检查
   `(player_id, beatmap_id)` 无重复。
2. 读两个 signal 表，取 `beatmap_id, d`；要求两张 signal 的 chart 集合相同
   （否则只做交集并显式标 `subset`，不能叫“主表 Δ”）。
3. 读 ceiling cache：
   `map_ids`、`cluster_ids`、`fold_of_cluster`、`seen_folds`。
   把 signal 的 chart 映射到 `map_ids` 的位置；若 `require-full-coverage`
   且交集不等于 `map_ids`，直接报错。
4. 按 `player_id` 建 groups；每个 group 的 cluster 取
   `player_id_base`（缺失时回退 `player_id` 并 warning，且要求每个
   `player_id` 只对应一个 base）；把 base 映射到 `cluster_ids` 的 compact index；
   对每个 group：
   * `fold = fold_of_cluster[c]`；
   * `seen = seen_folds[fold]`；
   * `ok = seen[a] & seen[b]`；
   * 只保留 `ok` 的 pair；记录 `ll_a`, `ll_b`, `y`, chart pair, cluster。
5. 在两个 signal 的 **全量 pair table** 上分别 `fit_link`（与主表一致），
   得到 `g_a`, `g_b`；在 strict pair 上算 NLL。
6. 断言 `n_strict == expected_n_strict`；断言
   `nll_a`/`nll_b` 与主表 `eval.json` 的 strict NLL 在 1e-9 内一致。
7. 输出 `delta = nll_a - nll_b`；同时输出 `delta_all`（旧口径）作对照。

player bootstrap：

~~~python
# cluster_of_pair: 每个 pair 的 player_id_base compact index
sum_a = np.bincount(cluster_of_pair, weights=ll_a, minlength=n_clusters)
sum_b = np.bincount(cluster_of_pair, weights=ll_b, minlength=n_clusters)
cnt   = np.bincount(cluster_of_pair, weights=np.ones_like(ll_a),
                   minlength=n_clusters)
for draw in rng.integers(0, n_clusters, size=(B, n_clusters)):
    m = np.bincount(draw, minlength=n_clusters)
    delta_b = (m * sum_a).sum() / (m * cnt).sum() \
            - (m * sum_b).sum() / (m * cnt).sum()
~~~

这里 **不能** 用 `mask[draw]=True`；重复抽中的 cluster 必须以 `m>1` 进入分子/分母。

chart bootstrap：

~~~python
m = np.bincount(draw, minlength=n_charts)
w = m[xa] * m[xb]          # xa/xb 是 strict pair 的两张图
if w.sum() == 0: continue
delta_b = (w * ll_a).sum() / w.sum() - (w * ll_b).sum() / w.sum()
~~~

### 5.4 测试

新增 `scripts/test_rank_paired_delta.py`：

1. **合成 strict 对齐**：手工构造 3 个玩家、6 张图、2 个 fold 的 ceiling；
   直接枚举 strict pairs 算 NLL，与脚本输出一致（≤1e-12）。
2. **重复 cluster**：同一 `player_id_base` 下两个 `player_id` 段；
   player bootstrap 的 `m>1` 必须等价于“把该 base 的所有段复制 m 次”，
   而不是只保留一次。
3. **chart multiplicity**：构造只有两张图重复抽中的情况，验证
   `m[a]*m[b]` 权重和手算一致。
4. **与主表一致**：在同一合成表上跑 `step2_rank_eval --strict-pairs`，
   比较 `n_strict` 和 NLL；再跑 paired 脚本，断言
   `delta == nll_a - nll_b`。

## 6. F4：K4 vs 全窗口的冻结对照

### 6.1 它回答什么

现有 unfrozen vs frozen same-head 的 0.020 差距，可能来自：

1. 行为梯度真的改善了表征；
2. 冻结臂只训练 K=4 个随机窗口，读出/聚合比全窗口弱；
3. 评测只取前 24 个窗口，长图覆盖不足。

F4 用**同一个冻结 D2V、同一个 ChartHead、同一个 pair sampler、同样的
1M pair views**（头训练，不是 encoder 训练），只改训练/评测窗口策略，做 2×2：

| 编号 | 训练窗口 | 评测窗口 | 作用 |
|---|---|---|---|
| C0 | K=4 随机 | cap 24（当前默认） | 重实现当前 frozen same-head 口径（不是旧 run 的 bitwise 复现） |
| C1 | 全部 | 全部 | 最强冻结读出（同头） |
| C2 | K=4 随机 | 全部 | 分离“评测截断” |
| C3 | 全部 | cap 24 | 分离“训练窗口覆盖” |

主对比：

~~~text
Δ_window = NLL(C0) - NLL(C1)      # 正 = 全窗口更好
~~~

分解：

~~~text
train_effect = NLL(C3) - NLL(C0)
eval_effect  = NLL(C2) - NLL(C0)
joint_effect = NLL(C1) - NLL(C0)
~~~

### 6.2 实现

新增 `scripts/e1_frozen_window_control.py`，不修改训练主脚本的模型：

1. 读 H4 split；过滤 `label_ok`；train/val/test 与 trainer 一致。
2. 加载 D2V，`requires_grad_(False)`，`eval()`。
3. 对 train/val/test 每张图，取全部不重叠窗口
   `window_starts(n_frames, 1600)`（不截断），逐窗口前向，得到
   `wv = mean_t f` 和 `vo = valid_frames`；写 `features.npz`：
   `chart_ids`, `offsets`, `wv` (默认 float32), `vo` (int32), `n_frames`。
   float16 只作为磁盘紧张时的可选项，且必须先验证 `wv` 聚合后的 `z`
   与 float32 的 max abs diff ≤1e-5。
4. 训练只更新 `ChartHead`：
   * pair sampler 复用 `sample_rows`，但用独立的 `pair_rng`；
   * 窗口选择用独立 `window_rng`，保证四格的玩家/图对序列相同；
   * K4：每图抽 4 个窗口（不足 4 用全部）；
   * all：用全部窗口（或 `--max-train-windows 0` 表示不截断）；
   * 聚合：`z = normalize(sum(wv*vo)/sum(vo))`；
   * loss：F2 的 `bt_loss`；
   * 预算：1,000,000 pair views；不早停；last 导出。
5. 评测：按 `cap24` 或 `all` 聚合 val/test，写 `d_test.parquet`。
6. 用 `step2_rank_eval --strict-pairs` 得到四格 NLL；用 F3 的 paired 脚本
   算 C1−C0 等 Δ/CI。

### 6.3 覆盖率先行

在跑四格前，先输出：

* 每张 test 图的 `n_windows_all`、`n_windows_cap24`；
* `frames_used/frames_total` 的分布；
* 有多少图 `n_windows_all > 24`。

如果 cap24 已经覆盖 99% 的图，F4 的评测截断效应会很小；如果长图很多，
这个表就是报告里必须给的 caveat。

### 6.4 判定规则

先看 `Δ_window` 和 C1 与 unfrozen 的距离。M4 先用 legacy unfrozen 的
确定性复评 NLL；clean seed 1 出来后用 clean 值复核判定，避免用旧的不确定
数字做最终结论：

| 情况 | 判定 |
|---|---|
| `Δ_window ≤ 0.003` | 窗口策略不是主要解释；H1a 的 0.020 不能归因于窗口 |
| `0.003 < Δ_window < 0.010` | 不确定；补 unfrozen all-window 或更多 seed |
| `Δ_window ≥ 0.010` 且 `|NLL(C1)-NLL(unfrozen)| ≤ 0.003` | 冻结臂的弱势很大一部分可由窗口/聚合解释；H1a 只能写成“相对弱冻结读出”，不能写成“微调全面胜出” |
| `Δ_window ≥ 0.010` 但 C1 仍比 unfrozen 差 >0.003 | 窗口不是唯一解释；H1a 仍可能是表征增益，继续 clean seed 1 |

同时把 C1 与 content-table D2V linear（0.57547，旧口径）比较；如果 C1 已接近
0.575，说明同头冻结的 0.5957 主要是读出/窗口问题，不是“冻结表征一定差”。

### 6.5 算力

冻结特征可缓存，四格只训练头，成本主要是：

* 一次 D2V 全窗口前向（~18k 图）；
* 四次 head-only 1M pair views（分钟级到十几分钟）；
* 评测/配对（CPU）。

估计 0.5–1 个 GPU 日；比重新训 encoder 便宜得多。

### 9.1 E2 文档修正（不跑 E2）

当前 `step2_chart_encoder.py` 里：

* `head` 产生 `d`；
* `event_head` 产生六档 logits；
* `judge_loss` 的梯度只经过 `event_head` 和 encoder；
* 如果 `--freeze all`，encoder 无梯度，`head` 也不接收 judge loss。

所以 A1（rank+judge）与 A0（rank only）的 `d` 在 frozen-all 下不会被辅助损失
改变；这个配置只能检验“冻结帧特征能否预测判定比例”，不能检验“判定比例是否
改善难度表征”。E2 若启动，主实验应使用：

1. `--freeze topk --unfreeze-blocks 4`（现有 E2 Slurm 已是这个），或
2. 冻结 encoder + 在两个头之前加一个共享可训练 adapter，使 judge loss 能进入
   共享参数。

E2 的数据核查/梯度验证可以并行准备，但**本计划不提交 E2**。

## 10. 风险与回退

| 风险 | 影响 | 回退 |
|---|---|---|
| GPU eval 仍有非确定性 | 小 Δ 不可信 | 固定 seed/确定性 flag；仍不行则 CPU 评分 |
| 旧 seed 1 没有 best，只有 last-save | 无法复现报告 best | 标 `last-available`；用 clean seed 1 作主结果 |
| ceiling cache 旧格式 | paired 脚本无法对齐 | cache v2；旧 cache 用 `--no-cache` 重算 |
| 信号 chart 集不一致 | Δ 不是主表 | 默认 `--require-full-coverage` 报错；只允许显式 subset |
| F4 全窗口特征太大 | 内存/磁盘 | float16 + 分块写 npz；只缓存 train/val/test |
| 队列限制 | 训练排队 | 串行提交；sentinel/autopilot；不轮询 |
| 修 loss 后结果变化大 | 旧结论不稳 | 不混表；legacy 和 clean 分开；必要时停止 seeds |
| 协议从 best 改 last 被质疑 | 事后选择 | 在跑 clean 前写死；best 作 secondary；报告解释原因 |
