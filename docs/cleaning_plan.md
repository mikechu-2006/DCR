## 1. 现有清洗步骤（已实现，作为基线）

### 1.1 构建期清洗（`scripts/legacy/build_v2.py` → `charts_v2_1k_v3.parquet`）

| # | 步骤 | 规则 |
|---|---|---|
| 1 | 谱面范围 | 只留真 4K mania：`playmode = 3` 且 `diff_size = 4` |
| 2 | 计分来源 | 只用经典计分：现代表（`scores.sql`）必须带 `CL`；legacy 表天然是 classic |
| 3 | mod 白名单 | 保留 `CL/MR/DT/NC/HT/SD/PF/NF`；剔除 `HD/FL/EZ/HR/FI/RD/...`（改变判定语义） |
| 4 | 标签 | `ACC = (300*(c300+cMAX) + 200*c200 + 100*c100 + 50*c50 + 250) / (300*(total+1))`，`L = log(1−ACC)`，伪 250 保证满分不发散 |
| 5 | 曲目定义 | `chart_id = beatmap_id*4 + rate`，`rate ∈ {NM, DT(含NC), HT}` —— 同一谱面的不同速率算不同曲目 |
| 6 | 剔除① | cell 中位 ACC < 0.90（乱打） |
| 7 | 剔除② | `(玩家, 谱面)` 的 `playcount ≤ 2`（真实游玩次数，含失败） |

### 1.2 收敛判定 v4（`scripts/legacy/convergence_filter.py` → `charts_v2_1k_conv.parquet`）

成绩按 `(year, doy)` 排序；末窗 = 最后 3 条（不足退化），前窗 = 紧邻的同样多条目。

| 量 | 定义 |
|---|---|
| `delta` / `adelta` | `mean(末窗) − mean(前窗)` / 其绝对值（loss 越小 = ACC 越高；**delta < 0 = 后段更好**） |
| `sd_tail` | 末窗内 loss 标准差 |
| `se_tail` | `sd_tail/√n_tail`；`t_delta = adelta/√(se_tail²+se_prev²)` |
| `span` | 首末成绩时间跨度（年）；`attempts` = playcount 表的真实游玩次数 |

三套口径（都写进输出表，`--criterion` 决定谁当 `conv_tier`）：

| 口径 | A 层 |
|---|---|
| abs（当时默认） | n≥5, span≥90d, attempts≥8, \|delta\|≤0.35, sd_tail≤0.5 |
| se | 同上但 `se_tail≤0.20, t_delta≤2.0` |
| joint | abs ∧ `t_delta≤2.5` |

v4 实测（1k，cell 级，dim16，wd=1e-4，10% cell 留出，target=loss_med）：

| 训练集 | cells | 曲目 | val RMSE | val R² |
|---|---|---|---|---|
| primary | 108,353 | 3,012 | 0.7737 | 0.8261 |
| A | 6,608 | 277 | 0.7108 | 0.5348 |
| A+B | 25,072 | 809 | **0.6315** | 0.7442 |
| 随机等规模对照 | 20,540 | 629 | 0.9881 | 0.7363 |
| A（标签=末窗中位数） | 6,608 | 277 | 0.7671 | 0.4781 |

10k（play 级）：primary 1.0612 → A 0.7764 / A+B 0.8627（baseline 已复现 README 的 1.0605/0.6043）。

### 1.3 标签噪声口径（split-half）

把每个 cell 的成绩**随机**对半分，各取中位数 `m₁,m₂`，`d = m₁ − m₂`：

```
SE_half = SD(d)/√2      ← 报告里用的口径（半样本中位数 SE）
SE_full ≈ SD(d)/2       （理想 i.i.d. 下全样本中位数的 SE）
理论上界：SE(median) ≈ 1.253·σ/√n     σ = 单次游玩抖动
```

实测校准（1k，n≥8 抽 4000 个 cell，B=200 bootstrap）：`SD(d)/√2` ≈ 1.18×bootstrap，`SD(d)/2` ≈ 0.84×，理论式 0.97–1.02×。跨集合比较不受影响。

1k 噪声：primary 0.637 → A 0.192 / A+B 0.247；等规模随机对照 0.637。
降噪来源分解：σ 小 2.1×、n 多 1.3×、残余漂移小 1.1×。

## 2. v5 判据修订

### 2.1 删除时间跨度门槛（已决定）

理由：跨度只影响"稳定状态持续了多久"，不改变"末段与前段是否重合"这一判定本身。
实测代价很小——去掉 `span ≥ 30d` 后，各档只多回 5–10% 的 cell：

| 档（n / \|Δ_med\|） | 全部 | 其中 span<30d | span<90d |
|---|---|---|---|
| n≥4 / ≤0.25 | 26,396 | 2,399（9.1%） | 5,009 |
| n≥5 / ≤0.15 | 12,725 | 948（7.4%） | 1,990 |

→ 结论：真正卡住数据量的是**抖动门槛与 n 门槛**，不是跨度。跨度保留为**报告字段**（`span`），不再当门槛。

### 2.2 删除末端抖动门槛（已决定，附证据）

判据不对 `sd_tail` 设门槛。三条实测理由：

**(a) 3 条成绩的 `sd` 基本由"最差的那一条"决定**（1k，n≥5，末窗 3 条）：

| 统计量 | 值 |
|---|---|
| 末窗 3 条的 sd（中位） | 0.280 |
| 去掉最差 1 条后的 sd（中位） | **0.106**（只剩 38%） |
| 只差 1 条成绩就会跨过 `sd ≤ 0.5` 门槛的 cell | **17.6%** |
| 同理跨过 `sd ≤ 0.8` | 9.6% |

也就是说 `sd_tail≤0.5` 在很大程度上是"**你最近有没有随手打过一把**"的检测器，而不是"水平是否停止变化"的检测器。

**(b) 漂移与抖动几乎是两个轴**：n≥4 的 cell 上 `corr(|Δ_med|, sd_tail) = 0.371`。

**(c) 漂移门槛换来的是"无偏"，不是"更准"**：在漂移通过集内继续收紧漂移，标签噪声几乎不动。

| 集合 | cells | 标签噪声 SE |
|---|---|---|
| primary | 121,200 | 0.661 |
| v4 A 层（含 sd 门槛） | 13,820 | **0.208** |
| D1 n≥5 & \|Δ_med\|≤0.15 | 12,725 | 0.331 |
| D2 n≥4 & \|Δ_med\|≤0.25 | 26,396 | 0.323 |
| D3 n≥4 & \|Δ_med\|≤0.35 | 34,266 | 0.332 |
| 被拒 n≥4 & \|Δ_med\|>0.5 | 37,851 | 0.767 |

→ 结论：**漂移回答"水平是否停下来了"（bias/stationarity），抖动回答"标签估得准不准"（precision）**。
前者当门槛，后者改成**权重**（见 2.5）。这比"用抖动当门槛"更符合本意，也不会因为一次随手打就丢掉整个 cell。

### 2.3 什么是"末段漂移"

**定义**：把该 cell 的全部成绩按时间排序，取

```
末段 = 最后 m 条     （m = 3；n=4~5 时 m=2；n=3 时 m=2）
前段 = 末段之前紧邻的 m 条（不足则取剩下的全部）
末段漂移  Δ = level(末段) − level(前段)          level 用中位数
判定：|Δ| ≤ δ  →  认为"最近一段的水平"和"之前一段的水平"重合，即已收敛
```

**它在问什么**：玩家的水平**是不是还在动**。若末段与前段重合，说明最近的成绩不是"新状态"，用整个 cell 的中位数当标签不会混进两种水平；若明显不重合（还在进步、或状态下滑），这个 cell 的标签就是混合量。

**和另外两个概念的区别**（这是本节的关键）：

| 概念 | 定义 | 回答的问题 | 对"随手打一把"的敏感性 |
|---|---|---|---|
| **末段漂移** | 末段水平 − 前段水平 | 水平**停没停**（收敛判据） | 低（中位数；一条成绩需跨过中位才影响） |
| 抖动 dispersion | 同一窗口内成绩之间的随机差 | 标签**估得多准**（精度） | 高（3 条时 sd 由最差一条主导，见 2.2a） |
| 趋势 trend | 整条序列的单调斜率 | 长期走向（学习曲线） | 中（需要很多点才估得准，且被早期主导） |

**为什么用中位数而不是均值**：一条"随便打的"成绩对 3 条均值的影响是固定的 1/3；对中位数只有在它跨过中位时才改变结果，且只移动一档。这正是你指出的问题。

**漂移方向不设符号**：v4 已实测 n≥6 的 cell 里 85% 的 `Δ < −0.05`（末段 loss 更低 = **末段 ACC 更高 = 打得更好**，是一条正常的学习曲线，见 [play_order_analysis.md](play_order_analysis.md)），所以判据取绝对值——不要求"已经停止进步"，也不要求"还在进步"，只要求末段水平不再单向漂移。

### 2.4 v5 判据与分层（1k 实测规模）

判据 = `n ≥ n_min` ∧ `|Δ_med| ≤ δ`；**不设** span、不设 sd 门槛。可选保留 `attempts ≥ 8`（练习深度，成本很小，见括号）。

| 档 | 条件 | cells | 占 primary | 曲目 | 玩家 | 标签噪声 SE |
|---|---|---|---|---|---|---|
| **D0** | n≥6 & \|Δ\|≤0.15 | 8,864 | 6.3% | 3,741 | — | — |
| **D1** | n≥5 & \|Δ\|≤0.15 | 12,725 | 9.0% | 4,900 | 647 | 0.331 |
| **D2（建议默认）** | n≥4 & \|Δ\|≤0.25 | 26,396 | 18.7% | 7,415 | 744 | 0.323 |
| **D3** | n≥4 & \|Δ\|≤0.35 | 34,266 | 24.2% | 8,133 | 770 | 0.332 |
| 被拒 | n≥4 & \|Δ\|>0.5 | 37,851 | 26.7% | — | — | 0.767 |
| 判不了 | n=3 | 59,478 | 42.0% | — | — | — |

加 `attempts ≥ 8` 只损失约 10%：D2 26,396 → 23,988（曲目 7,415 → 6,769）；D1 12,725 → 12,205。

**n=3 怎么办**：v4 里 42% 的 primary cell 只有 3 条成绩。两条路——
（a）默认丢弃（n≥4 才能构造两段比较，2 条 vs 1 条的漂移估计噪声很大）；
（b）可选 `T` 档：用该玩家**其它** cell 的抖动 `σ_player` 做参照，若 3 条的极差 `≤ c·σ_player` 则收录。
留出验证（1k，81,999 个 n≥4 的 cell，只用前 3 条判定，再用后续成绩检验）：通过组"后续成绩 vs 首3中位数"偏差 0.420（c=2.0）vs 未通过组 0.753、全体基线 0.505 —— **有效但弱**。
规模：c=2.0 时通过 28,847 个（n=3 的 48.5%，相当于 primary 的 20.4%）。
→ 定位：`T` 只作低置信补充档，默认不进训练集。

### 2.5 精度不再当门槛，改成权重

既然抖动不进门槛，就要在大样本量下把"每个 cell 的标签有多准"用起来。方案：

```
1) σ_cell 稳健估计：1.4826 · MAD(该 cell 的全部成绩)      # 对一条随手打不敏感
2) 向玩家层面收缩：σ̂² = (n·σ_cell² + k·σ_player²) / (n + k)，k = 3
   σ_player = 该玩家所有 n≥4 cell 的 σ_cell 的中位数
3) 标签标准误：SE_cell = 1.253 · σ̂ / √n
4) 训练权重：w = 1 / (SE_cell² + ε)（再归一化到均值 1）
```

训练时按 `w` 加权（cell 级或 play 级都可以；play 级用同一个 cell 权重）。
报告时按 `SE_cell` 分箱看 RMSE，能直接看出"误差是不是集中在脏标签上"。

## 3. 评估协议：固定 eval 集怎么选

### 3.1 先回答"只选筛过的 eval 集会不会偏袒清洗过的模型"

**会偏袒，而且偏袒的方向不一定是"清洗模型赢"——它首先会掩盖清洗的代价。** 两层机制要分开：

1. **协议公平性**：只要所有配置用同一个 eval 集、都不在 eval cell 上训练、打分限制在词表交集内，比较就是公平的。选哪些 cell 进 eval 不改变"公平"。
2. **问题定义（真正的偏差来源）**：eval 集决定了问什么问题，也决定了谁的短处被暴露。
   * eval = 只含收敛 cell → 问"谁最会预测练熟且干净的 cell"，同时**把覆盖率的代价藏起来了**：严筛模型对很多 (玩家, 曲目) 根本没有向量，但这些 cell 不在 eval 里，于是看不见。
   * eval = 全部 primary cell（最低限度预处理）→ 问"谁最会填满整个矩阵"，清洗的代价（覆盖 + 外推）会直接体现在分数上。
   * 另外，用**被处理过的**数据当测试集，是典型的"用后处理变量做条件"（conditioning on post-treatment selection）：过滤器是训练侧的处理手段，测试集不该由它筛。

**用我们自己数据的实测（1k，cell 级，mirt dim16）：** 取"base(primary 训练) 的留出 ∩ A+B 模型完全没训练过"的 cell，再限制到两模型词表都能打分：

| 子集 | cells | base(primary 训练) | A+B 训练 | A+B − base |
|---|---|---|---|---|
| 可打分覆盖率 | 8,715 | **100.0%** | **48.0%** | 严筛模型的覆盖代价 |
| 全部（primary 分布，共同可打分） | 4,187 | **0.6716** | 1.0041 | +0.3325 |
| ├ 收敛档 A/B | 231 | **0.4596** | 0.5992 | +0.1396 |
| └ 未收敛 none | 2,904 | **0.7270** | 1.0875 | +0.3605 |

（该 eval 集标签噪声 SE=0.656，扣噪 excess：base 0.142 / A+B 0.760）

三个结论：
* 只在自己的收敛集上评估，会把"A+B 只能覆盖 48% 的矩阵"这件事完全藏起来；
* 一旦换成最低限度预处理的 eval 集，严筛模型连**它自己的主场（A/B 档）都输了**（0.599 vs 0.460）—— 因为它的训练数据只有 1/4，参数方差更大；
* 所以"偏袒"不一定表现为"清洗模型虚高"，更常见的是**评价口径换掉以后结论反转**。

### 3.2 通行做法（这就是为什么主指标要用最低限度预处理集）

| 原则 | 在本项目里的落地 |
|---|---|
| 测试集必须来自**部署/目标总体**，不能由被评估的处理手段筛出来 | 主指标 = `E_full`（primary 全量的固定随机子样本）；收敛过滤器**只作用于训练集** |
| 处理手段算作"模型的一部分" | 清洗档位（D1/D2/D3）是训练侧超参，测试集对它们一视同仁 |
| 覆盖率必须显式报告，不能只报"能打分的部分" | 同时报"词表交集上的 RMSE"和"可打分覆盖率"；覆盖率 <60% 要标注 |
| 测试集脏不要紧，只要对所有人一样脏 | `E_full` 的噪声 SE≈0.66，会压缩差异但不偏袒任何一方；比较看 `excess` |
| 分组报告，暴露优势/劣势来自哪里 | 在 `E_full` 上再按"该 cell 属于收敛档/未收敛档"拆分（上表就是这么做的） |
| 预注册主对照，避免多重比较 | 主对照 = `D2 vs B0`；其余为探索性，报 paired bootstrap CI |
| 固定划分、固定 seed、按 cell 切分 | `eval_*_1k.parquet`，seed `20260928`，同一 cell 的 play 不跨集合 |

**回答"是不是应该用最低限度预处理的数据做 eval/test"：是，主指标就该这样。** 唯一的前提是"最低限度"必须对**所有**配置一致——在本项目里就是 §1.1 的 v2 清洗（它定义了 `primary` 这个总体，且所有简历配置都共用）。至于"干净子集上的表现"，那是一个**合法的、但不同的问题**，作为次要指标照报不误，只是不能当头条。

### 3.3 双 eval 集设计（固定，1k）

| 名称 | 抽取方式 | 规模（预计） | 角色 |
|---|---|---|---|
| **E_full（主）** | 从 primary 全部里按 (玩家, 曲目) 抽 10%（**不做任何收敛过滤**） | ~14,100 cells | 头条指标：整个矩阵填得多准 + 覆盖率 |
| **E_clean（次）** | 从 D1 ∪ D2 里按 (玩家, 曲目) 抽 20% | ~7,800 cells | 条件指标：干净子集填得多准 |

* 两个集合互斥（E_clean 优先，E_full 扣除），**从所有训练配置里一律剔除**，不管该配置筛没筛到它。
* 切分单位是 **(user_id, chart_id) cell**（同一 cell 的 play 全在 train 或全在 eval），避免泄漏。
* seed 固定：`rng = np.random.default_rng(20260928)`。
* **词表交集与覆盖率**：主口径只统计"user 与 chart 在所有被比较配置的词表里都出现"的 eval cell，报 RMSE/SE/excess；同时报每个配置的**可打分覆盖率**，把覆盖不到的部分单独列出来（§3.1 那张表就是模板）。

### 3.4 指标定义（只看 stage-1 矩阵填充）

| 指标 | 定义 | 说明 |
|---|---|---|
| **RMSE** | 在 eval 集上算 | 主指标，loss 单位；头条用 E_full，E_clean 为次要 |
| **SE** | 该 eval 集的 split-half 标签噪声（§1.3） | 每个 eval 集算一次，所有配置共用 |
| **excess** | `√(max(RMSE² − SE², 0))` | 扣掉标签噪声后的"模型误差"，跨配置可比 |
| **覆盖率** | 能打分的 eval cell 占比 | 严筛的代价，必须报 |
| paired CI | 同一 eval cell 上 bootstrap 重采样（配置间配对差值） | 判定"是否真的更好" |
| 附：Spearman | 预测值与标签的秩相关 | 只看排序质量时用（可选） |

不看 R²（不同集合 target 方差不同，会误导）；**不用** stage-2 指标。

## 4. 训练侧改动（1k 优先）

| 项 | 现状 | v5 | 理由 |
|---|---|---|---|
| 训练集 | primary / v4 A+B | **D2（默认）**，对照 D1、D3、primary | §2.4 |
| 权重 | 无（或 n_scores） | `w = 1/SE_cell²`（§2.5） | 抖动不进门槛后，精度用权重表达 |
| 词表门槛 | `--min-map-players 20` / `--min-player-maps 20` | 10 / 10（D2 下 7,415 曲目） | 集合变小，20/20 会把曲目砍到几百 |
| `dim` | 16 | 8 与 16 两档 | 26k cell 撑 16 维 item 向量偏多 |
| `wd` | 1e-4 | 1e-4 与 3e-4 | 同上 |
| 早停 | 固定 60 epoch | patience 10、相对 min_delta 1e-5（顺带修 `train_stage1.py` 里 `best` 被反复覆盖的 bug） | 小数据 + 固定轮数会过拟合 |
| 随机性 | 单次划分 | 3 个 seed，报 mean±sd | 集合小了，单次划分不稳 |
| eval | 随机 10% 留出 | `--eval-cells` 指向 E_clean / E_full | §3.2 |

## 5. 实验矩阵与验收标准（1k，仅 stage-1）

| 编号 | 训练集 | 权重 | dim/wd | 说明 |
|---|---|---|---|---|
| B0 | primary（现有 primary 全量） | — | 16 / 1e-4 | 基线（在同一 eval 集上重算，不用旧数字） |
| C1 | v4 A+B | — | 16 / 1e-4 | 旧判据锚点 |
| C2 | **D2** | — | 16 / 1e-4 | 主候选 |
| C3 | D1 | — | 16 / 1e-4 | 更严 |
| C4 | D3 | — | 16 / 1e-4 | 更宽 |
| C5 | D2 | **1/SE²** | 16 / 1e-4 | 权重是否补回精度 |
| C6 | D2 | 1/SE² | 8 / 3e-4 | 小数据配置 |
| C7 | D2 ∪ T（可选） | 1/SE² | 16 / 1e-4 | 覆盖换纯度的对照 |

**验收标准（先定好；主指标只看最低限度预处理集）**

1. **主指标（E_full，最低限度预处理集）**：`excess` 低于 B0，且 paired bootstrap 95% CI 上界 < 0 —— 这是唯一算"成功"的条件；
2. **覆盖率硬约束**：E_full 上可打分 cell ≥ 60%（低于此，无论 RMSE 多好都视为不可用，见 §3.1 的 48% 例子）；
3. 次要指标（E_clean）：`excess` 也应低于 B0；两个 eval 集上都要按"该 cell 属于收敛档 / 未收敛档"分组报告；
4. 训练集自身噪声 SE ≤ 0.35（D2 实测 0.32，门槛 0.35 是可达的）。

任一条不达标 → 退一档（D2→D1→v4 A+B）或调 δ，并把结论写回文档与 README。
